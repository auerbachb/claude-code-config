# PMM Pre-Dispatch Gate

`pmm-pre-dispatch.sh` is called inside the persistent Monitor's shell loop before the loop emits a
PMM chat event. The Monitor is an out-of-turn process whose stdout lines become chat events; its
shell is therefore the supported pre-model boundary. Do not call the full PMM skill on a quiet
tick and then suppress its prose: that already paid for a model dispatch. The mechanism and observed
Monitor behavior are recorded in `.claude/reference/bgwork-ceiling.md` and
`.claude/reference/token-efficiency-audit-2026-07.md`.

## Contract

- Successful unchanged collection: empty stdout, exit 0. The Monitor emits no chat event and the
  model is not invoked. Meaningful wakes use the existing PMM entry and its selected phase references; this bounded pilot does not claim a full split of that entry.
- Meaningful transition: one `/pr-monitor-and-manage --tick ... --dispatch-event <id>` invocation.
  The compact event packet is persisted in the outbox, and the skill reads it by the exact ID
  before acting. It contains repo/author context, PR IDs and HEADs for fleet changes/findings,
  changed PR projections, finding IDs, evidence paths, trigger, and detection time/latency where
  comment timestamps are available. Keeping it in state lets Monitor stdout contain exactly one
  chat event per transition (and one same-ID event per pending replay).
- Unknown, stale, malformed, or failed collection: a diagnostic event, never a clean/unchanged
  verdict. Ordinary helper output/errors are captured or sent to stderr, so stdout stays empty on
  a quiet tick. If state persistence itself fails, one `/pr-monitor-and-manage --tick ... --pre-dispatch-diagnostic` line wakes the
  operator/model and asks the next Monitor tick to retry; it cannot be acknowledged as a durable
  event and runs diagnosis only before any PR action.
- The exact persistent shell command is generated by `pmm-pre-dispatch.sh --monitor-command`, with validated shell-quoted absolute paths and configuration literals. It runs without caller shell variables. Monitor generation is minted once before arming and embedded in both command and publication. Configuration/version changes stop the exact old Monitor before replacing it.

- The outbox is stored at `.pmm_pre_dispatch.pending_event` through `session-state.sh`. Delivery is
  at-least-once: the same event ID is re-emitted until an exact-ID acknowledgement arrives after
  the full PMM tick's discovery, current gate/ownership checks, authorized actions, Step 7
  lifecycle work, and state writes. Separate durable actions and lifecycle receipts let a repeated
  delivery re-run fresh checks, skip completed Step 5 actions while reusing completed Step 6 state and finishing Step 7, and
  acknowledge the same ID only after lifecycle completion. A crash between an external action and
  writing that receipt remains governed by each action's existing lock/idempotency contract; the
  event ID does not promise cross-system exactly-once execution. A mismatched acknowledgement
  cannot clear the pending event.
- Current-head merge-gate and PR ownership checks remain authoritative in the ordinary PMM tick.
  Pre-dispatch evidence only decides whether to wake the model; it cannot authorize a PR mutation.
- Direct owner messages enter as ordinary interactive turns and bypass the scheduled-tick gate.

## Projection and wake predicates

The collector reuses `gh pr list`, `merge-gate.sh`, `pr-state.sh`, and the canonical
`lib/pr-state-classify.jq`. It compares fleet membership; HEAD, merge/review/CI/blocker state; new
actionable finding source IDs and body hashes; active agent, PMM lock, and merge-sequencing hold transitions; and their
safety/recovery deadlines.
Finding IDs are checked independently of the coarse merge-gate projection, so a new actionable
comment still wakes when the ordinary state digest is unchanged. A finding packet includes IDs and
URLs rather than full comment bodies; the evidence bundle path is passed for the normal PMM module
to inspect.

Active Phase A agent deadlines follow PMM's existing windows: 15 minutes for PMM-owned
`pmm-fix-*` records and 60 minutes for foreign records. Active `/wrap` locks use the existing
60-minute stale-lock window. Due IDs are persisted once so an acknowledged deadline does not wake
on every later tick; a changed record gets a new deadline key. Missing or malformed timestamps
produce `deadline_state_unknown` and wake immediately. The separate deadline-unknown fingerprint
continues local checks and re-notifies on observations 1, 4, 7, and so on for the same keyset; a new
keyset wakes immediately. This durable unresolved state is not treated as clean.

Collector diagnostics also keep a fingerprint separate from deadline state. A new failure reason
wakes immediately; identical acknowledged failures retry locally on every poll and re-notify on
observations 1, 4, 7, and so on. A healthy collection clears the collector-error streak. Until then,
the prior snapshot and unresolved fingerprint are retained: failures wake only for a new reason or
at that repeat interval, and are never recorded as a clean comparison. A pending event always
replays with its original ID before either retry policy runs.

CAS updates are confined to `.pmm_pre_dispatch`: concurrent acknowledgement/receipt writes cause a retryable diagnostic instead of overwriting one another. Old-generation shell processes exit before collection; a newly published generation retains an old outbox as `superseded_event` and performs fresh comparison. A bounded 64-entry acknowledgement history makes delayed delivery benign after newer events have completed. Pending replays increment tick/dispatch/replay counters while meaningful transitions remain counted separately.

Unreleased merge holds wake for a sequencing recheck on the next poll: the existing sequencing helper owns tick-based stall release, so suppressing those polls would strand held work. Released audit entries do not prevent idle convergence. Quiet polls advance scheduling counters; event polls leave the increment to PMM Step 6, and actions-receipt replays reuse the completed counters instead of counting twice.

The collector keeps the prior snapshot across process restarts and records tick, dispatch,
transition, and cumulative error counts, with a separate consecutive `error_streak`. A persisted transition sequence prevents two same-second changes from sharing an event ID. A new Monitor identity forces an initial scan. It validates each
PR-state bundle against required comment/check fields, PR/repository identity, collection time, and both the discovered and fresh merge-gate HEAD before
classification. Unknown ownership/merge state, malformed input, future timestamps, and snapshots/bundles older than
one hour wake for a fresh comparison; this bound is intentionally independent of the quiet-state
digest. Within one generation pending events are not overwritten while waiting for acknowledgement, so changes observed
after a delayed event are compared on a later tick.

## Runtime integration limits

The repository documents Monitor stdout-to-chat-event behavior, but a Codex-hosted implementation
task cannot live-arm Claude Code's Monitor tool. Local replay verifies that the gated Monitor
command emits zero bytes for unchanged state and emits a retryable event for changes/errors. The
PMM skill bumps `.pmm_pre_dispatch_version` so its first tick replaces an older Monitor command
that directly emitted a model event without this shell gate.

Focused executable replay: `.claude/scripts/tests/pmm-pre-dispatch.test.sh`.
