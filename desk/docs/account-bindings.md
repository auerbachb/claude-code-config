## Account bindings (issue #2183)

Every Claude account is explicitly bound to one queue. There is no fallback to `public`.

- **Identity.** An account is its config directory: `CLAUDE_CONFIG_DIR` when set and non-empty, else `$HOME/.claude`, with `~` expanded, made absolute, and trailing slashes removed. The match is lexical on purpose (no symlink resolution, no case folding), because Claude Code derives a credential realm from the spelling. A differently spelled alias is unbound and refused, never mapped.
- **Registry.** `${XDG_CONFIG_HOME:-~/.config}/human-queue/bindings.tsv` lives outside every profile, so copying `settings.json` leaves the binding in place. Registry writes set the directory to mode 700 and the file to mode 600. Keep both paths owner-only. The readers validate file type and row contents. Each tab-separated row stores the account directory, name, and queue schema. The connection URL is configured separately.
- **Guard.** `desk-cli.sh` resolves the queue from the registry before every subcommand except `bindings`, `bind`, and `carry-over`. An unbound account exits 4 with "You can't run the desk here until you configure a queue for this account" and the bind command, before any store contact or `register-control`. The capture hook renders the menu, queues nothing, and prints one warning line naming the bind command. A malformed registry (a duplicate or bad row) fails closed.
- **Commands.** `desk-cli.sh bind --name <name> --schema <schema> [--config-dir <dir>] [--rebind]` migrates the queue, then records the binding; a different existing queue needs `--rebind`. `desk-cli.sh bindings` lists accounts and queues. `desk-cli.sh carry-over [--profile <dir>]... [--dry-run]` binds the default directory to `public` as `personal`, and each profile to the `HUMAN_QUEUE_SCHEMA` in its `settings.json`, then removes that interim entry.
- **Tests.** `desk/tests/bindings-offline.test.sh` covers the guard, isolation, `bind`, `bindings`, the hook, bash/python agreement, corruption, and carry-over, all against temp directories.

## Queue owner (issue #2184)

The queue remembers the account it belongs to, so a hand-edited or copied registry row that names a different account cannot point a second account's desk at someone else's queue. A copied row that keeps the owner's name still passes; see What the check does not stop.

- **The stamp.** `bind` (and `carry-over`, which runs `bind`) runs `owner set NAME`, the only path that stamps a queue: it writes the binding NAME, for example `personal`, under the reserved state key `queue_owner`, and does nothing else to the queue. `state set` refuses that key. The stamp is a name, not a path: two machines that bind the same name to the same queue agree.
- **The check.** `register-control`, `tick` (sessionless ticks too), and `add` (the capture hook's and external capture's write) compare the caller's binding name with the stamp inside the same transaction, under a shared advisory lock that `owner transfer` takes exclusively. A mismatch exits 4 with one line naming both sides, and writes nothing. `desk-cli.sh` and both capture hooks pass the name from the registry (`HUMAN_QUEUE_BINDING`); a real account's name never comes from the environment.
- **Unstamped queues (decided).** A named call against a queue with no stamp refuses (exit 4) with instructions to run `bind`; the hook fails open, rendering the menu with one warning line. Only `bind` and `carry-over` stamp, so an ordinary call never does. An unnamed call against an unstamped queue is unchanged from before (there is no owner to compare, and nothing is stamped). An unnamed call against a stamped queue refuses, so a raw call cannot skip the check.
- **Rebinding a queue (decided).** `owner transfer NAME` is the explicit queue-side move. Without `--confirm` it writes nothing and prints the open-item count; `--confirm` writes the new owner. After a transfer, the account binds again with `bind --name NAME --schema SCHEMA`, which then matches. `bind --rebind` still changes only the account side.
- **Tick loop.** A `tick --session` refused for ownership makes `desk-tick.sh` print one `stopped` line and exit 4. It does not retry on the cadence.
- **Test seam.** `HUMAN_QUEUE_SCHEMA=hq_test_*` honors `HUMAN_QUEUE_BINDING` only when that name also starts with `hq_test_`. Any other name is ignored, so the seam cannot name a real account. Unnamed test calls keep working on unstamped schemas. `desk/tests/queue-owner.test.sh` stamps throwaway schemas with `hq_test_` names.
- **What the check does not stop.** It compares names only. A copied registry row that keeps the owner's name still passes the three guarded commands; a row that names a different owner, or a call from a profile whose name differs, is refused. Two accounts that share one name are one account to the queue.
- **Signed-in identity (decided: name only).** The stamp does not record the account's signed-in identity. The hook and CLI see only the config directory and the environment. The signed-in account is held in profile state that this code must not read, and no reliable non-secret signal is exposed to a hook. A stored email would also put personal data in the queue. A profile re-logged into another account therefore still matches its name. Revisit only if Claude Code exposes an account identifier to hooks without reading credentials.

## One queue per account, setup notice, and start display (issue #2185)

- **One queue per account.** Each account is bound to exactly one queue, and a queue has one owner. A new account starts unbound: nothing is inherited from the primary install, and a copied profile never arrives linked to another account's queue.
- **Commands.** `desk-cli.sh bind --name <name> --schema <schema> [--config-dir <dir>] [--rebind]` creates the binding. `desk-cli.sh bindings` lists every account. `desk-cli.sh bindings --current` prints `account: <name>  queue: <schema>` for the account in use, reading only the registry, so it works without a database URL.
- **Refusal: unbound account.** Every desk command except `bindings`, `bind`, and `carry-over` exits 4 with the bind command. `bindings --current` exits 4 with the same sentence and never contacts the store.
- **Refusal: queue owned by another account.** `bind` refuses a queue whose owner is a different name (exit 4, nothing recorded). Moving a queue is `owner transfer`, described above.
- **Start display.** `/desk` runs `bindings --current` first, before `migrate`, the hold read, and `register-control`. An unbound account is refused before the store is touched. Otherwise the start report shows the account and queue before the first tick.
- **Setup notice.** `ai-quotas-setup.sh share-config` on a Claude profile strips any `HUMAN_QUEUE_SCHEMA` entry from the copied `settings.json` and reports it as `stripped HUMAN_QUEUE_SCHEMA from settings.json` (the value is never printed). A rerun reports the copy as `kept`. A source that mentions the key but is not valid JSON exits 5 and leaves the profile's `settings.json` alone. After the summary, one nonfatal line for the profile: `desk queue: <name> (<schema>)`, or `no desk queue — run <bind command>` naming the profile's config directory, or `desk queue: unknown (<reason>)` when the desk or registry cannot be read. The desk is found through `HUMAN_QUEUE_DESK_DIR`, then `~/.claude/skills-worktree/desk`. Codex profiles get no line.
